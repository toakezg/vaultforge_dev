# Icon Set Generation Workflow Contract

Status: workflow contract. No apply tool or folder-icon application is approved
by this document.

## Purpose

Define the first safe workflow for turning a list of directories, subfolders,
and short descriptions into a generated icon proposal set.

The intended user shape is:

```text
make an icon set for these dirs in style X
```

where each target has a path and a short description.

## Inputs

Allowed input sources:

- proposal inbox files under `vaultforge-icon/generated/proposals/inbox/`
- a user-provided directory list and descriptions
- a user-provided style guide, such as `f:\media\icons\my_icons\style-guide.txt`
- an approved directory scout report generated by an agent

Do not read private or unrelated files deeply unless the task explicitly scopes
that directory scout.

## Roles

Use one full rotation per meaningful batch, not one role per icon.

- Coordinator: sets target folders, style source, output folder, count, gates,
  and cycle budget.
- Directory Scout: inspects scoped folders and writes descriptions into the
  proposal inbox or run folder.
- Inspiration Scout: turns descriptions and style notes into visual directions.
- Builder: writes prompt files and runs `run_icon_proposal.ps1` or a later
  approved set runner.
- Reviewer: checks output count, metadata, visual review readiness, scope drift,
  and filetype/apply feasibility.
- Recorder: updates `TASKS.md`, `CHANGELOG.md`, `SIGN_UP.md`, run logs, and any
  apply-plan follow-up.

## Output Shape

Each run should write to a named folder under:

```text
vaultforge-icon/generated/proposals/<run-id>/
```

Recommended contents:

- `PROPOSAL.md`
- `RUN_LOG.md`
- `targets.md`
- `style.md`
- `prompts/*.txt`
- `images/*.png`
- `images/*.json`

For icon sets, use one prompt file per target unless Coordinator chooses a
smaller sample first.

## Set Style Rules

An icon set may be:

- unified: same shape language and different colors/symbols
- semi-unique: shared frame plus unique subject per folder
- unique: each folder gets its own visual identity, still with shared quality
  and size constraints

Record which mode is being used before generation.

## Apply Chain

Applying generated icons is not part of the generation workflow.

After review, a later task may create an apply-plan that checks:

- target path exists
- icon source is selected and approved
- output format is usable for the target
- the filetype or folder supports icon application
- existing icon state and rollback note are recorded
- Nath has approved applying icons

Folder-icon application remains gated until `$apply-icon` or a manual apply
task is explicitly approved.

## Stop Gates

Stop and tag `#nath` for:

- unscoped directory scanning
- secrets or new cloud auth
- asset moves/deletes
- folder-icon application
- selecting final winners when taste matters
- changing ownership between icon, engine, art, or business lanes

## First Good Test

A good first test is a media-folder proposal set using the inbox style guide:

- video / active playback: orange or gold
- mixed/general media: blue or cyan
- images/gallery: green
- audio/sound: purple
- raw/unassigned: white or neutral

Generate a small proposal batch first, review it, then decide whether to expand
into a full set.
